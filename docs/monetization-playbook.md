# Реклама на сайте: план включения (Adsterra)

**Статус: код готов, реклама ВЫКЛЮЧЕНА.** Слоты, consent-бар и страница
`/privacy` уже в проде, но `AD_CONFIG.enabled = false` — ни один рекламный
запрос не выполняется. Включение = одна команда + деплой (см. «День
включения» ниже).

Вся операция занимает ~1 час. Сайт: https://estiem-horoscope.netlify.app

---

## Что уже есть в коде

| Файл | Что делает |
| --- | --- |
| `app/lib/ads-config.ts` | Главный выключатель `AD_CONFIG` (сейчас `enabled: false`) + ключ Adsterra |
| `app/lib/ads-consent.ts` | Хранение GDPR-согласия в localStorage (`estiem-ads-consent`) |
| `app/components/ads.tsx` | `AdSlot` (баннер 300×250 в iframe) и `AdConsentBar` (Accept/Decline) |
| `app/routes/privacy.tsx` | Страница `/privacy` — политика конфиденциальности (нужна для доверия и модерации) |
| Размещение слотов | `/` (после сетки знаков), `/signs`, `/signs/<знак>` (после навигации вперёд/назад) |
| `scripts/enable-ads.mjs` | Переключает выключатель и прописывает ключ одной командой |
| Футер | Ссылка «Privacy» на каждой странице |

Как это работает:

- Реклама показывается **только после нажатия «Accept»** в consent-баре
  (GDPR: аудитория европейская). «Decline» → рекламные запросы не летят вовсе.
- Баннер живёт в собственный `srcdoc`-iframe: классический сниппет
  Adsterra использует `document.write`, который безопасен только в своём
  документе — так он не ломает нашу SPA-страницу и работает при переходах.
- Вокруг слота зарезервировано точное место 300×250 → сдвига макета (CLS)
  нет, SEO не страдает.
- Слот ничего не рисует, пока выключатель `false` — вкладка в бюджете
  Netlify (деплой = 15 кредитов из 300/мес) не расходуется впустую.

---

## Когда включать (порог по трафику)

Реклама при малом трафике приносит центы и добавляет только шум. Критерий:

- **GA4: стабильно ≥ 2 000–3 000 просмотров/мес.**
- Где смотреть: GA4 → Reports → Engagement → Pages and screens (или
  Home → Views за месяц).
- Ожидание при RPM ≈ $2–4 за один слот: 3 000 просмотров ≈ **$6–12/мес**,
  10 000 ≈ $20–40/мес, 100 000 ≈ $200–400/мес.

Если решили включить раньше — включайте: ничего сломанного не будет, просто
доход будет символическим, а Adsterra будет считать показы «пустыми».

## День включения — чеклист (~1 час)

### 1. Аккаунт Adsterra (15–20 мин)

1. adsterra.com → **Sign up** (роль — publisher).
2. **Add website**: `estiem-horoscope.netlify.app`, категория
   (Entertainment/Lifestyle), язык — English.
3. Дождаться одобрения сайта (обычно моментально, допускается до 24 ч).
4. Создать формат **Display Banner 300×250** → в сниппете появится
   строка вида `atOptions = { ... 'key': 'xxxxxxxx' }` — это **Website key**.
5. Скопировать ключ (алфавитно-цифровая строка).

Условия: выплата **от $5**, способы вывода — в личном кабинете
Adsterra → Payments. Мелкий мини-FAQ по форматам: берём только display
300×250, никаких popunder/push/interstitial (см. «Правила» ниже).

### 2. Включить — одна команда

Выполнить (PowerShell, из папки проекта):

```powershell
# 1) включаем слоты и прописываем ключ
node scripts/enable-ads.mjs <ADSTERRA_KEY>

# 2) коммит + пуш (PAT подставляется в момент выполнения, в файлы не сохраняется)
git add -A
git commit -m "Enable advertising (Adsterra display banners)"
$pat = "<GITHUB_PAT>"
$b64 = [Convert]::ToBase64String([Text.Encoding]::ASCII.GetBytes("x-access-token:$pat"))
git -c credential.helper= -c "http.extraheader=AUTHORIZATION: basic $b64" push origin main

# 3) деплой
$env:NETLIFY_AUTH_TOKEN = "<NETLIFY_TOKEN>"
corepack pnpm dlx --package=netlify-cli netlify deploy --build --prod --site e8cd4e3b-d743-4243-b2e0-feeab0785da7
```

**Проще: сказать ассистенту** — «включаем рекламу, ключ `<KEY>`» — и он
выполнит весь чеклист сам (аккаунт Adsterra заводите вы, остальное работа
ассистента).

Токены (PAT, Netlify) вводятся в момент операции и **никуда не пишутся** —
не сохраняйте их в файлах репозитория.

### 3. Проверка (10 мин)

1. Открыть сайт **в приватном окне**: внизу consent-бар → **Accept** →
   на `/`, `/signs` и `/signs/aries` появляется блок **Advertisement** с
   баннером 300×250.
2. Нажать **Decline** в другом приватном окне → баннеров нет, запросов к
   `highperformanceformat.com` нет (проверить в DevTools → Network).
3. В Adsterra → **Statistics**: показы начинают накапливаться в течение дня.
4. Днём: `/privacy` открывается без входа, кириллицы нет, футер с
   «Privacy» на месте (CDP-смоук ассистента).

### 4. Откат, если что-то не нравится

```powershell
node scripts/enable-ads.mjs --disable
# затем: commit → push → deploy (как в шаге 2)
```

Реклама выключается полностью, ключ остаётся в конфиге для будущего.

## Правила (чтобы не потерять трафик и позиции в Google)

1. **Запрещено**: interstitial (реклама при переходе между страницами),
   popunder, push-подписки, full-screen. Google понижает такие сайты в
   выдаче (intrusive interstitials), аудитории ESTIEM это чуждо.
2. **Не больше 1 слота 300×250 на страницу** (уже так и стоит). Больше
   слотов — только после того, как первый даёт стабильный доход.
3. **Не чаще одного прод-деплоя в день**: каждый деплой = 15 кредитов из
   300/мес (см. бюджет Netlify). Правки собираем пачкой.
4. Реклама не должна перекрывать контент гороскопа и кнопки навигации.
5. Consent-бар не убирать — без него показ рекламы европейским посетителям
   юридически спорен.

## Что отложить на будущее

- **Google AdSense** — подключать при ≥ 10–20к просмотров/мес: качество
  рекламы и RPM выше, но модерация «вручную» и порог вывода $100.
  Место под слот уже есть, смена сети = новый ключ + (возможно) новый
  сниппет в `app/components/ads.tsx`.
- **Consent-бар и для GA4** — сейчас Google Analytics работает без
  согласия; отдельная небольшая задача, если захотите закрыть и это.
- **Второй слот** — появляется только когда первый приносит деньги и
  трафик это оправдывает.
